PHASE 1 — MAKE THE BACKTEST TRUSTWORTHY
========================================

1. AUDIT THE ENTIRE BACKTEST CODE [DONE]
---------------------------------
Go through the complete backtest engine and strategy code and understand exactly how every step works.

Check:
- How raw data is loaded 
- How higher-timeframe candles are created
- When candles become available
- How VWAP is calculated
- When signals are generated
- How entries and exits are executed
- How stops and targets are handled
- How transaction costs are applied
- How the equity curve and drawdown are calculated

Goal:
Be able to explain exactly what the backtest is doing and identify assumptions that differ from live trading.


2. AUDIT COMMON BACKTESTING MISTAKES
------------------------------------
Create a checklist and verify the engine against common backtesting problems.

Check for:
- Look-ahead bias
- Future data leakage
- Higher-timeframe leakage
- Incorrect candle timing
- Unrealistic entry/exit prices
- Intrabar ambiguity
- Missing or duplicate data
- Corporate actions
- Liquidity assumptions
- Transaction costs
- Slippage
- Session boundaries
- Position sizing
- Capital constraints
- Short-selling assumptions

Goal:
Reduce the difference between what the backtest assumes and what could actually happen in live trading.


3. FIX REALISTIC ENTRY EXECUTION
--------------------------------
The current strategy generates signals from completed 5-minute candles.

Make sure the backtest does not assume that you can magically trade at the exact candle close after the candle has already completed.

Test realistic alternatives such as:
- Next 1-minute open
- Next available price
- Entry price plus/minus realistic slippage

Goal:
Measure the effect of the delay between signal generation and actual order execution.


4. ADD REALISTIC SLIPPAGE
-------------------------
Add and test realistic slippage instead of using zero slippage.

Run multiple scenarios, for example:
- ₹0.00/share
- ₹0.02/share
- ₹0.05/share
- ₹0.10/share
- ₹0.20/share

Goal:
Understand how sensitive the strategy is to execution costs and determine whether the edge survives realistic trading conditions.


5. BUILD A SIMPLE 10-DAY EYEBALL TEST
-------------------------------------
Create a very simple strategy/test that can be manually checked over a small period such as the last 10 trading days.

The purpose is not to make money.

The purpose is to verify that:
- Signals appear where expected
- Entries happen at the expected time
- Exits happen correctly
- Stops and targets behave correctly
- The trade ledger matches what can be seen on the chart

Goal:
Have a small, manually verifiable test case for validating the backtesting engine.


6. COMPARE TRADES WITH THE CHART
--------------------------------
For the 10-day test, manually compare every trade with the price chart.

Check:
- Entry candle
- Entry price
- Direction
- Stop
- Target
- Exit candle
- Exit price
- Reason for exit

Goal:
Confirm that the backtest is actually taking the trades you think it is taking.


7. VALIDATE THE VWAP IMPLEMENTATION
-----------------------------------
Research and independently verify the VWAP calculation.

Check:
- Correct VWAP formula
- Meaning of each variable
- Why volume is used
- Session reset behaviour
- Price definition used by the implementation

Also compare the current implementation against an independently calculated VWAP using the same raw data.

Goal:
Prove that the VWAP used by the strategy is actually the VWAP you intended to use.

PHASE 5 — OPTIMIZATION
======================

16. BUILD A SYSTEMATIC STRATEGY OPTIMIZATION WORKFLOW
------------------------------------------------------
Create a workflow that can repeatedly run the backtest while changing parameters.

Potential parameters:
- Momentum threshold
- Stop loss
- Target
- Maximum trades per day
- Maximum losses per day
- Other strategy-specific parameters

Save the result of every test.

Goal:
Make optimization reproducible instead of manually changing parameters and running the backtest.


17. AVOID OVERFITTING DURING OPTIMIZATION
-----------------------------------------
Do not simply choose the parameter combination with the highest historical return.

Track:
- Number of parameter combinations tested
- Performance stability around the best parameters
- In-sample results
- Out-of-sample results
- Performance across multiple assets
- Performance across different market periods

Goal:
Find robust parameters rather than parameters that only fit historical noise.


18. OUT-OF-SAMPLE VALIDATION
----------------------------
After choosing a strategy/parameter set, test it on data that was not used during optimization.

Goal:
Check whether the apparent edge survives on unseen data.

      ↓

      ↓
FORWARD/LIVE TEST
      ↓
OPTIMIZE
      ↓

      ↓

The objective is not to make the backtest return as high as possible.

The objective is to determine whether the strategy has a real, repeatable edge that can survive realistic trading conditions.
